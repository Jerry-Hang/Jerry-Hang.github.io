# 被限制用电脑的夜里，我用中端安卓机跑通了原生 dsh 和 Codex

起因其实没什么特别的，只是网页版 Chatbox 用着太难过了。推理强度调不了，联网搜索要花钱，稍微长点的代码一复制就断，体验非常割裂。加上那段时间电脑使用被限制，大半夜开电脑又吵又亮，我就想看看手里这台**中端安卓机**到底能不能干这些活，能不能像电脑一样让 AI 接上环境自己迭代项目。

于是，我开始了这场持续到凌晨四点的折腾。

## 第一部分：Termux 与 dsh 的部署，以及绕不开的安卓底层坑

首先是环境。一定要去 **F-Droid** 下载 Termux，应用商店的版本是停更的，会直接报错。安装好后，第一时间换源，用 `termux-change-repo` 选清华或浙大镜像，否则更新列表和下载包的速度会让你怀疑人生。

换好源，安装 Node.js，准备跑 DeepSeek 的 Harness。刚编译原生模块就撞上了第一堵墙：

```
fatal error: 'spawn.h' file not found
```

这个问题在电脑上根本不会出现，但在安卓上非常致命。因为安卓底层用的是 **Bionic libc**，它原生不包含标准的 POSIX `spawn.h` 头文件，而 Harness 依赖的原生 C++ 库（koffi）非要调用它，导致编译流程直接卡死。硬着头皮搜了一圈，发现社区里有个专门为安卓适配的 fork，原理很简单：写一个空的 shim 头文件骗过编译器，再把安卓上支持极差的硬链接（`link` 系统调用）强制替换为 `rename` 操作。靠着这套补丁，dsh 终于勉强在手机浏览器的 `127.0.0.1:3080` 上跑了起来。

## 第二部分：安卓调度策略的"死父母"行为与 Termux 权限死磕

跑通 dsh 之后，我开始尝试给 Termux 提权，想让它拿到系统级权限，这样就能控制硬件或防止后台被杀。

我通过 **Shizuku 和 rish** 进入了系统 Shell。这一步进去容易，出来难。在系统 Shell 里，`~` 会被解析成根目录下的 `//`，而不是 Termux 的私有目录，导致我执行 `mkdir -p ~/.termux/boot` 时直接报错 **Read-only file system**，文件根本创建不了。

更尴尬的是，因为我在 `.bashrc` 里加了自动进权限的命令，导致 Termux 每次启动都会强制跳进系统 Shell，用 `exit` 退出会直接让整个程序闪退。我卡在里面出不来，普通指令也执行不了。最后只能通过 MT 管理器或者用 `run-as com.termux` 来强行修改 `.bashrc`，删掉那行自动跳转的命令，才把环境救回来。

这还没完。安卓系统的后台调度策略极度严格，像极了"死父母"式的高压管控。即使我在设置里给了"完全允许后台行为"和"无限制"耗电，锁屏一段时间后，系统的深度休眠（Doze）机制依然会强行切断本地服务的网络连接，导致 `127.0.0.1:3080` 页面变成无法访问。

最后只能通过 Shizuku 授予的系统权限，执行：

```bash
sh ~/rish -c "dumpsys deviceidle whitelist +com.termux"
sh ~/rish -c "cmd appops set com.termux RUN_IN_BACKGROUND allow"
```

把它加进系统白名单，才勉强稳住了后台。

## 第三部分：Codex 的部署与惨烈的 Rust 编译

dsh 跑通后，我又动起了装 OpenAI Codex 的念头。

首先尝试常规的 `npm install -g @openai/codex`，直接报错提示缺少 **@openai/codex-linux-arm64**。查了一下原因，是因为 OpenAI 官方根本没有给安卓的 ARM 架构编译预构建好的二进制包，所以 npm 装不上，只能走 Rust 源码编译。

我通过 `cargo install --git https://github.com/openai/codex --force` 拉取源码，但很快又撞上了 `rama_error::OpaqueError` 的报错。研究后发现，这是因为主分支在开发阶段锁死了一个半成品的 alpha 依赖包，导致代码和依赖库的版本对不上。最后加上 `--tag rust-v0.45.0 --locked` 强行锁定依赖版本，才总算进入了编译阶段。

这才是真正煎熬的开始。**1367 个 Rust 包**需要全部在手机上编译，手机没有风扇，处理器要面对长时间高负荷运转。从我按下回车的那一刻起，手机温度直线上升，摸起来像个**暖手宝**。屏幕上的编译进度条以极其缓慢的速度跳动着，期间绝对不敢按 Ctrl+C，因为一旦中断就得从头再来。

编译过程持续了整整 **24 分 49 秒**，我全程盯着屏幕，看着手机忍受着这种远超日常使用的负荷，直到最后一行字提示安装成功。那一刻，这台 **骁龙 7s Gen 3** 手机，终于在本地跑起了 OpenAI 的 Codex CLI。

---

最后总结一下：折腾了一整晚，手机成功变成了两个 Agent（dsh 和 Codex）的宿主。验证了安卓端跑原生产物的可能性，但也必须承认，手机受限于散热和系统调度，无法发挥全部算力，只能作为应急工具使用。如果以后有条件，还是老老实实用电脑，但那个半夜在手机上硬啃编译器报错的夜晚，确实给了我一种**挖穿墙的解脱感**。
